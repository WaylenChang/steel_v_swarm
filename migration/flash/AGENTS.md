# Flash — bounded UI and settings

## Scope

Apply the root ownership rules. This workstream owns the UI allowlist there and
this directory. Default to Gemini Flash for tasks with an existing source
contract, a small edit surface and directly observable acceptance.

Read this file, then [MIGRATION.md](MIGRATION.md), then only the selected task's
source producer, UI consumer and dedicated fixtures. Do not preload sibling
backlogs or model research. Run commands from the repository root.

## Implementation contract

- Use existing native Controls, containers, timers, labels and imported glyphs.
- Display source data and submit existing commands. Never settle HP, resources,
  purchases, readiness, permissions or match outcomes in a panel.
- Keep source strings, colours, thresholds and defaults in generated data.
  Changes to source extraction/publication require the owning workstream.
- Preserve rejection versus silence, event deduplication, stable ordering and
  rounded-zero active values. Do not make UI state invent gameplay restrictions.
- Read existing helpers before adding one; edit only the selected behavior.
- If the task requires a new protocol, source algorithm, shared shader or
  producer change, record the exact owner handoff in this directory's backlog.
  Finish independent UI work; keep unsupported controls explicitly unavailable.

## Acceptance

Compare with the original producer, not screenshots alone. Check empty/missing
metadata, repeated events, death/observer/room transitions, portrait/landscape,
safe-area layout, text wrapping and persisted-setting restoration as applicable.
Run the dedicated suite and a real rendered scene for layout changes. Runtime
changes also require the root fixture/smoke/transport gates; only Opus edits their
shared registration files. A documentation edit needs link/scope checks only.

## Context and updates

Keep instructions stable. Only this directory's `MIGRATION.md` receives task
updates or handoffs; remove finished items instead of recording their history.
Append task evidence after these instructions in the conversation. Do not edit
another workstream's documents or modify root files for routine progress.
